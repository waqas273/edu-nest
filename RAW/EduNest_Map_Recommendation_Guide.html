1System Actor Integration & Workflows

EduNest orchestrates maps and matching algorithms across two primary user actors: the Student (seeking optimal academic paths) and the University Manager (onboarding campuses and publishing program catalogues).

⚠️ Location Access Requirement

Location Permission Enable Karna Lazmi: Both actors must enable browser location services. Managers need GPS to drop campus pins accurately, and students need it to calculate real-time proximity scores.

A. University Manager Workflow (Onboarding & Catalog Management)

The manager's flow acts as the primary data ingestion pipeline for campus locations and degree options:

  • Step 1: Registration & Onboarding: Upon approval, the manager completes onboarding (UniversityOnboarding.jsx). The page mounts the LeafletLocationPicker UI.
  • Step 2: Campus Geolocating: The manager enters their address. The picker hits the Nominatim Search endpoint to retrieve exact GPS latitude/longitude. Alternatively, the manager clicks on the visual grid to drag/position the pin. Reverse geocoding resolves and updates the address text automatically.
  • Step 3: Database Serialization: On submit, onboarding profile parameters are saved inside the Firestore users collection. Mapped fields include latitude (number), longitude (number), location (address text), and city.
  • Step 4: Degree Cataloging: The manager navigates to their profile panel (ManagerProfile.jsx). They create programs (BS/MS) which populate the Firestore degrees collection with a reference mapping to their manager universityId.

B. Student Workflow (Discovery, Evaluation, & Navigation)

The student's flow utilizes these records to match personal indicators against published campus datasets:

  • Step 1: Interest Discovery: The student registers and completes the AI Career Assessment. The output determines their top academic interest (e.g., Computer Science, Biology) and home city, saved inside their student profile.
  • Step 2: Recommendations Calculation: The student lands on the discover panel (Universities.jsx or StudentPrograms.jsx). The browser triggers a geolocation API request. The system runs the scoring engine utility on the loaded universities and programs, comparing academic matches, proximity, and ratings.
  • Step 3: Spotlighting: Scoring results above ≥50 points are sorted descending and displayed in a high-priority "Recommended for You" section. Interactive badges indicate the `% Match` rating and mark nearby options as "In Your City".
  • Step 4: Visualizing & Navigation: The student clicks "View Profile" (mounting UniversityDetails.jsx). The system initiates the LeafletCampusView. The student can toggle satellite views, inspect the pulsing pin, and click "Open in Google Maps" to launch external navigation routes.

2Free Leaflet Map Integration Architecture

EduNest implements an open-source, coordinate-based mapping layer utilizing Leaflet.js and the OpenStreetMap (OSM) Nominatim APIs. By choosing this stack over commercial options (such as Mapbox or Google Maps Javascript SDK), EduNest runs entirely fee-free, eliminating credit card bindings and usage caps.

LeafletLocationPicker.jsx

Use Case: Renders inside the university onboarding flow and manager profile page. Allows managers to search their physical address via forward geocoding, drop pins manually, and automatically reverse-geocode to find coordinates and city structures.

LeafletCampusView.jsx

Use Case: Renders on the student dashboard's university profiles page. Displays campus pins with a glassmorphic vector popup containing quick-link directions triggers.

Forward Search Geocoding LeafletLocationPicker.jsx (Onboarding / Manager profile) Translates text addresses to coordinate structures via Nominatim Search API:
https://nominatim.openstreetmap.org/search?q={Query}&format=json&limit=6&countrycodes=pk
Debounced at 400ms to prevent API hammering. Limits results to Pakistan.
Reverse Geocoding LeafletLocationPicker.jsx (On Map Click event) Extracts textual address metadata on pin drop via Nominatim Reverse API:
https://nominatim.openstreetmap.org/reverse?lat={Lat}&lon={Lng}&format=json
Extracts city/town/village and returns address payload parameters.
Theme-Aware Tile Toggling Both Picker and Viewer components Uses a React MutationObserver attached to the root document.documentElement. Automatically toggles active tile sheets:
• Light Mode: CartoDB Voyager (/rastertiles/voyager/{z}/{x}/{y})
• Dark Mode: CartoDB Dark Matter (/dark_all/{z}/{x}/{y})
Satellite Map Overlay Both Picker and Viewer overlays Leverages Esri ArcGIS World Imagery tiles:
https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}
Pulsing SVG Markers Both Map Views Custom SVG pins wrapped in Leaflet's L.divIcon. Prevents production image bundler asset scaling issues and includes a pulsing radial backdrop shadow.

Fallback Architecture: If the university profile does not have coordinates configured, the system falls back gracefully to a Google Maps search iframe inside LeafletCampusView.jsx:
https://maps.google.com/maps?q={UniversityName}+{City}&output=embed

3Dynamic Hybrid Recommendation Engine

EduNest contains a hybrid scoring utility (src/utils/recommendationEngine.js) that computes matching scores between a student's profile (career interests, home city, coordinates) and approved universities and programs in real time.

Overall Recommendation Score Formula
Score(100 Pts) = (Academic Interest Match × 50%) + (Geographical Proximity × 30%) + (Review Ratings Strength × 20%)
Minimum score threshold to be displayed in "Recommended for You" section: 50 Points

A. Factor 1: Academic Interest Matching (Max 50 Points)

Career interests matched via AI student profiles map to database degrees using a keyword dictionary.

  • University Level Matching: Matches all verified degrees for a university. If ≥ 3 degrees match: 50 pts. If 2 degrees match: 45 pts. If 1 degree matches: 40 pts. If 0 matches: 0 pts.
  • Program Level Matching: Matches program title directly against interests. Direct hit: 50 pts. Mismatch: 0 pts.
Computer Science computer, software, cs, it, coding, web, ai, data science, cyber, network
Biology bio, medical, mbbs, bds, pharma, zoology, botany, genetics, microbiology
Mathematics math, mathematics, statistics, actuarial, algebra, calculus, quantitative
Physics physics, physical, electronics, electrical, mechanical, civil, engineering

B. Factor 2: Geographical Proximity (Max 30 Points)

If the browser geolocation API fetches coordinates dynamically, the physical distance is calculated using the Haversine Formula. If coordinates are denied, it falls back to city name string matching.

The Haversine Distance Formula
d = 2R · arcsin ( √ sin2(Δlat / 2) + cos(lat1)·cos(lat2)·sin2(Δlng / 2) )
Where R is Earth's radius (6,371 km), and d is calculated physical distance in Kilometers
  • GPS Calculation Rules:
    • Distance ≤ 15 km: 30 Points (Nearest local area)
    • Distance ≤ 50 km: 20 Points (Close proximity)
    • Distance ≤ 150 km: 15 Points (Moderate distance)
    • Distance > 150 km: 10 Points (Far distance)
  • Text Fallback Rules: If GPS is disabled or coordinates are empty, the system checks:
    isLocationMatch(UniLocation, StudentCity) ? 30 : 10 (Substring match gives 30 pts; mismatch 10 pts).

C. Factor 3: Ratings Strength (Max 20 Points)

Scores authority based on the average star ratings from the reviews collection:
• Equation: Round( (Average Rating / 5.0) * 20 )
• Blank-State Fallback: If a university has no reviews yet, it defaults to a rating of 3.5 stars (yielding 14 points) to remain fair and avoid bias against new campuses.

4Frontend Flows & Database Integration

The scoring engine is loaded into both the universities explorer page (Universities.jsx) and the global program directory (StudentPrograms.jsx) to sort, badge, and spotlight matches.

A. React Component Integration & Lifecycle Flows

  • Universities.jsx:
    1. Mounts and requests device coordinates via navigator.geolocation. Saves output to studentCoords.
    2. Fetches approved university managers from the users collection.
    3. Queries the reviews and degrees collections in parallel for each university to compute ratings and list degrees.
    4. Maps the documents through `getUniversityScore()`. Slices the top 6 scoring `≥ 50` matches into a "Recommended for You" grid.
  • StudentPrograms.jsx:
    1. Loads programs from the degrees collection.
    2. Loads the student's submitted applications from the admissions collection to display active submission badges (accepted, rejected, pending).
    3. Runs `getProgramScore()` and filters programs matching the student's interest category.
    4. Renders a premium horizontal scrolling carousel spotlighting programs with `% Match` and local city tags.
