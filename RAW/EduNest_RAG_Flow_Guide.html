1Introduction & Core Concept

In our original entry test module, questions were generated using basic client-side prompt engineering. While fast, this method had three major issues: (1) the AI made up facts or equations that were not part of the local FSc syllabus (hallucinations), (2) raw API keys were exposed in the frontend browser, and (3) questions did not reliably follow official marking blueprints.

To solve this, we migrated the system to a RAG (Retrieval-Augmented Generation) pipeline. RAG behaves like an "open-book exam." When generating tests, the system queries local textbook PDFs, extracts the actual chapters, and instructs the AI to generate questions using only that text.

System Architecture & Data Flow

The system is split into two phases: the offline document ingestion pipeline (setting up the book database) and the online exam generation API.

Why this layout matters

By moving the vector calculation and query assembly logic onto the server, our client-side React app never holds secret API keys. The keys are safely stored in a hidden .env file in the Python backend directory.

2Offline Ingestion Pipeline (`ingest.py`)

The ingestion script turns raw, readable PDF textbooks into a vector search database. This process happens offline once, indexing all required study materials into our database directory.

1
Folder Scanning
The script scans the python_backend/data/syllabus/ folder. Folders are structured by subject and grade level (e.g., chemistry_11, physics_12) to map chunks to metadata correctly.
2
Text Extraction & Cleaning
Using pypdf.PdfReader, text is extracted page-by-page. Empty pages, scanned diagrams, or corrupted characters are skipped to ensure only high-quality searchable text is cataloged.
3
Overlapping Chunking
Text is split into 800-character blocks with a 100-character overlap. The overlap keeps sentences and paragraphs connected, preventing important topics from getting split across chunks.
4
Vector Embedding & ChromaDB Insertion
Chunks are sent in batches of 50 to OpenRouter's openai/text-embedding-3-small API, which turns text into 1536-digit coordinate lists (embeddings). ChromaDB indexes these lists on disk.

Under the Hood: Chunking & API Embedding Code

# Chunk batches are embedded using the OpenRouter Embedding Endpoint
payload = {
    "model": "openai/text-embedding-3-small",
    "input": batch_chunks
}
response = requests.post(
    "https://openrouter.ai/api/v1/embeddings",
    headers={"Authorization": f"Bearer {api_key}"},
    json=payload
)
embeddings = [item["embedding"] for item in response.json()["data"]]

# Store vector list & metadata in local ChromaDB
collection.add(
    ids=batch_ids,
    documents=batch_chunks,
    embeddings=embeddings,
    metadatas=batch_metadatas
)
Local Machine Optimization

We switched from a local SentenceTransformer model to OpenRouter's REST embeddings API. This prevents the python backend from downloading massive PyTorch models (over 200MB in size), reducing the system's memory footprint to near zero.

3Live Exam API Server (`app.py`)

The Flask backend server handles requests through a dedicated endpoint: /api/generate-rag-exam. When called, the route searches ChromaDB and triggers the language model to generate structured exam questions.

1
Query Embedding
The API embeds the queried subject name (e.g. "Physics") using the OpenRouter API to create a 1536-dimensional search coordinate vector.
2
Database Semantic Search
The vector is matched against textbook entries in ChromaDB. The database returns the top 5 context chunks matching that subject using cosine similarity distance.
3
Few-Shot past paper reference mapping
The backend pulls a random solved past-paper question from a local past_papers.json file. This template instructs the AI on the correct style and formatting layout.
4
Balanced Prompt Formulation & Llama 3.3 Inference
The prompt orders the model to output a strict JSON list of questions using the textbook context, with a balanced difficulty layout: 30% Easy, 50% Moderate, and 20% Hard.

Prompt Formatting & Fallback Handling

# Structuring the instructions sent to Groq Llama 3.3
prompt = f"Generate EXACTLY {count} unique MCQs for the subject '{subject}'..."
prompt += f"CONTEXT FROM FSC TEXTBOOKS:\n{context}\n\n"
prompt += f"STRICT BLUEPRINT: 30% Easy, 50% Moderate, 20% Hard.\n"
prompt += f"Return ONLY a raw JSON array. Schema layout:\n"
prompt += "[ { 'question': '...', 'options': ['A)...', 'B)...'], 'answer': '...', 'explanation': '...' } ]"

try:
    response = groq_client.chat.completions.create(
        model="llama-3.3-70b-versatile",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.3,
        response_format={"type": "json_object"}
    )
except Exception as err:
    # Outage fallback: returns pre-solved questions instantly from local past papers database
    questions = get_offline_fallback(subject, count)
Double-Layered Error Protection

If (1) the internet goes down, (2) the AI model is rate-limited, or (3) the AI outputs invalid JSON syntax, exception handlers catch the issue and serve pre-written past paper questions immediately. The student's testing session is completely protected from crashes.

4Student Portal & Test Engine (`MockExam.jsx`)

The student portal and test engine manage exam execution, cheating warnings, and custom grading patterns.

Exam Selection & Blueprints

Students choose their exam type in the dashboard. The client loads the configuration blueprint from aiExamService.js:

  • MDCAT (PMDC): 180 questions (Bio 81, Chem 45, Phys 36, Eng 9, Logical 9) | 180 Mins | No negative marking (+1 correct, 0 incorrect/unattempted).
  • ECAT (UET): 100 questions (Math 30, Phys 30, Chem 30, Eng 10) | 100 Mins | Negative marking (+4 correct, -1 incorrect, 0 unattempted).

Dynamic Mock Exam Run-Time

1
Database Session Creation
When starting a test, the app creates a record in Firestore (test_history) with a status of started. If the student exits early, the status updates to aborted.
2
Strict Anti-Cheat Warnings
A visibilitychange listener detects when the student switches browser tabs. The student receives warning overlays for the first two switch events. On the 3rd switch, the test auto-submits.
3
Practice vs. Test Mode
Subject-specific practice tests run in Practice Mode, allowing the student to check answers instantly. The correct option turns green, incorrect options turn red, and an explanation card displays. Full mock exams hide these checks until the end of the test.

Pakistan Blueprint Grading Code

// Score calculations matching official Pakistan entry test blueprints
let correctCount = 0;
let incorrectCount = 0;
let unattemptedCount = 0;

questions.forEach((q, idx) => {
    const userAns = answers[idx];
    if (userAns === undefined || userAns === "") unattemptedCount++;
    else if (userAns === q.answer) correctCount++;
    else incorrectCount++;
});

let score = correctCount;
let maxScore = questions.length;
if (isEcat) {
    score = (correctCount * 4) - incorrectCount; // ECAT Negative Marking Formula
    maxScore = questions.length * 4;
}

5Concept Video Bot & Walkthrough

The AI Concept Video Companion is an interactive study helper. If a student gets stuck on an exam question, they can search for the concept inside the app's video search bar to load matching video lectures.

Key Video Bot Features

  • Focused YouTube Search: Search keywords automatically append education-focused tags (e.g. "FSc intermediate chemistry lecture") to filter out general entertainment.
  • Bookmarks (LocalStorage Cache): Students can click the bookmark icon on any card to save it. The list is serialized and saved in localStorage under edunest_saved_videos so it persists across browser restarts.
  • Built-in Overlay Player: Videos play in a dark, full-screen overlay popup inside the app, preventing students from getting distracted by going to the main YouTube website.

Concrete Step-by-Step Scenario

The sequence below traces the student's experience when interacting with the RAG system and video companion:

1
Subject Practice Selection
A student chooses Chemistry Practice Mode. The backend embeds the topic "Chemistry" and retrieves textbook chunks about Bohr's Theory of Atomic Hydrogen.
2
Question Generation & Attempt
The AI generates a physics/chemistry calculation: "Find the angular momentum in the 3rd orbit (mvr = 3h / 2π)." The student selects choice A (1.5 h/π). They click "Check Answer." The card lights up green and explains the math step-by-step.
3
Accessing Video Bot Helper
Struggling with the angular momentum equation, the student goes to the Concept Video bar. They search "Bohr's Atomic Model angular momentum". The app displays three relevant YouTube lectures.
4
Watching & Bookmarking
The student opens the overlay player, watches the video tutorial, and bookmarks the lecture card to save it to their dashboard for future reference.
Summary of Benefits

This integration connects dynamic, grounded assessments with instant visual learning. It gives students a complete preparation loop: self-testing, checking work, and finding video resources, all inside a secure, monitored dashboard.
