1Executive Summary & Core Objectives

EduNest is an AI-powered educational counseling, exploration, and admission ecosystem designed to guide intermediate (FSc) students through their university transition. The platform consolidates interest assessment, academic roadmaps, university comparisons, transport maps, admission applications, community discussions, and entry test preparation into a unified platform.

The system leverages Machine Learning (ML) to run interest predictions, Natural Language Processing (NLP) to generate study roadmaps, neural networks inside the client browser to block toxic content, and Retrieval-Augmented Generation (RAG) to generate syllabus-grounded, zero-hallucination entry test questions.

3Core Cloud Databases Schemas

The platform operates with four key collection schemas defined inside Firebase Firestore to link profiles, admissions, and institutional credentials:

👤
Users Collection (`/users/{uid}`)
Stores auth profiles. Fields include: `role` (Student, Manager, Admin), `isApproved` (manager gate), `city` (for maps), `academicProfile` (matric/inter %), and `interest` (assessment prediction result).
🏛️
Universities Collection (`/universities/{id}`)
Stores university listings. Fields include: `name`, `logo` (Cloudinary URL), `description`, `coords` (geopoint), `programs` (references), `rating` (averaged reviews), and `infrastructure` (photo arrays).
🎓
Degrees Collection (`/degrees/{id}`)
Aggregated program explorer. Fields: `degreeName`, `universityId` (pointer), `category` (CS, Pre-Med), `feePerSemester`, `duration`, `seats`, and `eligibilityCriteria` (minimum FSc %).
📝
Applications Collection (`/applications/{id}`)
Admissions pipeline. Fields: `studentId` (pointer), `universityId` (pointer), `selectedDegree`, `matricRoll`, `resultCard` (Cloudinary file link), and `status` (Pending, Approved, Rejected).

5Functional Modules Deep Dive: Modules 1–4

A. Authentication, Onboarding & Security

During student registration, the React app triggers EmailJS to send a 6-digit OTP verification code to the student's email, which must be matched to activate the account. When a university manager registers, they submit credentials and institutional proof. React Router guards check their `isApproved` status from Firestore, preventing dashboard access until an Admin marks it as `true`.

Cloudinary Image Upload Engine: To avoid database overhead, images are hosted on Cloudinary via its client-side REST API. It uses `uploadToCloudinary` for profile pics and faculty headshots, and concurrent `Promise.all` batch uploads (`uploadMultipleToCloudinary`) for campus infrastructure galleries, transport buses, and academic result cards, ensuring faster load times without blocking the UI.

B. Interactive Maps & Location Services

During university onboarding, managers search for coordinates or drag a pin on a Leaflet map. Geocoding (address search) is powered by Leaflet and the Nominatim API without requiring paid external keys. On the student portal, Leaflet renders the campus location using light or dark theme-aware layers (CartoDB Voyager or CartoDB Dark Matter). Custom SVG icons are utilized instead of default Leaflet markers to prevent production build issues.

C. Student Counseling & Interest Assessment

Standard student counseling uses a Random Forest Classifier trained in Python and hosted on the Flask microserver. The frontend maps adaptive quiz responses (70 questions across 7 fields: Computer Science, Mathematics, Physics, Biology, Chemistry, Psychology, Graphics) into a 15-dimensional vector. The Flask `/predict-step` endpoint uses the model's `predict_proba()` method to compute real-time probability estimates for the fields.

The quiz adapts dynamically: Phase 1 asks baseline questions from each category. If interest in a single category crosses 75%, it skips straight to Phase 2. Phase 2 asks harder drill-down questions. If the student answers "Yes", it proceeds; if "No", the engine applies a 40% penalty decay to that field's score and switches to the second highest category. Phase 3 uses contrast questions as tie-breakers if scores are close after 18 questions.

D. Study Roadmaps & Resource Integration

Based on the predicted interest, the system queries the Groq API (Llama 3.3) to generate a structured JSON timeline of milestones and sub-topics, saved to Firestore under `/roadmaps`. Each topic in the roadmap includes an interactive Learning Hub with integrated tutorial aids:

  • 🎥 YouTube Video Tutorials: Dynamically fetches video tutorials using the YouTube Search API v3 based on a query combining the skill and topic title. If the API key is inactive, it falls back to a curated local set.
  • 🎓 Offline Coursera Recommendation Engine: Embeds a local dataset of Coursera courses. It scores courses using a local heuristic: exact skill match (+100 points), keyword match (+30 points), topic specificity (+80 points), rating boost (+15 * rating), and irrelevant noise penalty (-500 points). The top 15 highest-ranked courses are displayed.

5Functional Modules Deep Dive: Modules 5–11

E. AI Hybrid Recommendation System

When a student searches for universities, the system ranks listings using a custom scoring formula: $$\text{Score } (100) = \text{Academic Match (50%)} + \text{Geographical Proximity (30%)} + \text{Review Ratings (20%)} $$ The system scans degrees for terms related to the student's interest to assign the Academic Match (up to 50 points). Proximity is calculated using the browser's Geolocation API against campus coordinate variables using the Haversine Formula to compute distance.

F. Student Admissions & Application Builder

Students compile their academic credentials (matriculation/intermediate scores) and upload their result cards directly to Cloudinary. The system constructs an admission application worksheet. The application is compiled on the client-side and converted into an A4 PDF using the html2pdf.js library, enabling students to download their worksheets.

G. Financial Aid & Scholarship Systems

Onboards national scholarship schemes (e.g., HEC Needs Based, PEEF, university-specific merit grants) with a central eligibility matcher. When a student updates their academic profile, the system filters matching scholarships based on board, intermediate percentage, and household income thresholds, highlighting deadlines and application URLs.

H. Centralized Academic Programs Explorer

Consolidates all degree programs across onboarding universities into a single explorer catalog. Students search, filter by discipline (CS, Engineering, Medical, Arts), semester fees, and eligibility scores, resolving the fragmentation of programs scattered on separate university websites.

I. Transport Routing & Bus Locator

Managers onboard university transit routes, bus numbers, and stops. Leaflet maps display bus paths overlaid on the campus map, allowing students to check route coverage, proximity to their location, and calculate travel times based on geocoded routes.

J. Moderated Community Chatrooms

A real-time forum using Firestore listener subscriptions allows students, managers, and admins to interact in distinct rooms (e.g., General, CS, MDCAT prep). To maintain a clean environment, a client-side toxicity filter is integrated:

  • 🛡️ TensorFlow.js Toxicity Classifier: Intercepts all chat posts in the browser. It scans text locally across 7 categories (insults, threats, slurs, etc.). If confidence in any category exceeds 85%, it blocks publication and triggers an alert warning, keeping the forum safe without backend overhead.

6Proposed RAG Ingestion Pipeline & Architecture

To support MDCAT and ECAT entry test preparation, the system implements a secure, local Retrieval-Augmented Generation (RAG) pipeline. This pipeline generates syllabus-grounded mock test questions, ensuring that the questions match FSc textbooks and preventing out-of-syllabus terms or errors common in general LLMs.

The architecture is split into an offline ingestion pipeline and a runtime question generation sequence:

Fig. 2 — RAG Offline Ingestion Pipeline
  • 📄 Offline Ingestion: FSc Textbook PDFs (Physics, Chemistry, Biology) in `python_backend/data/syllabus/` are read page-by-page using `pypdf`, chunked into overlapping passages (500–1000 chars), embedded into 384-dimensional vectors via a local CPU-based `all-MiniLM-L6-v2` model, and indexed in a local `ChromaDB` store.
  • ⚙️ Runtime Search & Prompt Augmentation: When the student selects a syllabus topic, the Flask app converts the topic query to a vector, finds the top 3–5 matching paragraphs in ChromaDB, and inserts these paragraphs as grounding context into the prompt template.
  • 🧠 Zero-Hallucination Generation: The augmented prompt is sent to the server-side Groq Llama 3.3 API, which generates multiple-choice questions (MCQs) restricted strictly to the context. The generated questions are validated into a clean JSON structure containing questions, options, and correct answers, and returned to the React frontend.

Security & Cost Feasibility

The local embedding search processes queries at zero operational cost, requiring no external vector database fees. Private LLM API credentials are secure as they are stored inside Flask server environment variables, never exposed to client-side scripts. In case of API limits or network issues, a local backup file (`fallback_mcqs.json`) is maintained to ensure uninterrupted mock test generation.
