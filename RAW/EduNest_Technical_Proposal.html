1Step 1: Data Collection & Preparation

The first step is gathering all the academic reference resources. To make sure the AI extracts real text without formatting issues, we only keep clean, high-quality, text-selectable PDF files.

We collected official curriculum textbooks and yearly solved entrance papers (MDCAT/ECAT) from authorized portals. Any scanned photocopy or image-only PDF is automatically filtered out and deleted.

Directory Layout on the Server

python_backend/data/

In addition to the textbook PDFs, we catalog solved past papers into a unified reference JSON file. This allows the backend to retrieve real question formats to show the AI how MDCAT and ECAT questions look.

2Step 2: Text Extraction

Once clean PDFs are stored, the server reads them to extract the raw text. For this task, we use the Python library PyPDF.

PyPDF reads textbooks page-by-page, extracts raw text strings, filters out redundant whitespace or encoding errors, and yields a clean continuous stream of textbook chapters.

3Step 3: Text Chunking (Splitting) & Overlap

Textbooks are too long for the AI to read at once. We break long chapters into smaller, manageable paragraphs called **Chunks** using the **LangChain** library's **RecursiveCharacterTextSplitter**. We set the chunk size to **800 characters** (about 120 words).

To prevent formulas or concepts from being cut off in the middle, we implement a **100-character overlap** between consecutive chunks. The end of Chunk 1 is repeated at the start of Chunk 2. This keeps the semantic context continuous.

4Step 4: Vector Embeddings Generation

Computers cannot search raw text conceptually. We must convert each text chunk into a list of numbers representing its meaning. This list is called a **Vector Embedding**.

We use a small, locally-running AI model called all-MiniLM-L6-v2 (from the SentenceTransformers library). This model encodes each textbook chunk into a 384-dimensional vector coordinate in a semantic space.

5Step 5: Local Database Storage (ChromaDB)

We store the generated vectors, raw text chunks, and metadata (Subject, Class, Chapter) into a local database called ChromaDB. It runs embedded inside the python backend, saving data to local SQLite files without needing cloud servers.

6Step 6: Context-Augmented Prompt Construction

After retrieving the relevant textbook paragraphs (Context) and a sample past paper question (Style), the server constructs an augmented prompt to instruct the AI model.

Structured Prompt Template
System Instruction:
You are an FSc exam generator. Generate 10 MCQs from the Context.

[TEXTBOOK CONTEXT]
A projectile is thrown at an angle. Horizontal distance is X = Vi*cos(θ)*t.
Vertical height is Y = Vi*sin(θ)*t - 0.5*g*t^2.

[STYLE REFERENCE]
Options format must match: A) Option1  B) Option2  C) Option3  D) Option4

Constraint: Generate MCQs ONLY from the textbook context provided.

7Step 7: AI MCQ Generation (Groq Llama 3.3)

The server sends the prompt to the **Groq Llama 3.3** model. Because Llama 3.3 is given the exact textbook text, it cannot make up values or ask out-of-syllabus questions. The model returns a clean JSON list of generated questions.

API Request (POST) Backend Process API Response (JSON)
{ "subject": "physics", "topic": "projectile motion" } Retrieves text, sends prompt, receives Llama response. [ { "question": "...", "options": [...], "answer": "B" } ]
System Backup & Offline Fallback

If the internet is down, the Groq API key is rate-limited, or the LLM output is malformed, the Flask backend automatically catches the error and falls back to a database of pre-loaded offline past paper MCQs, keeping the system 100% reliable.
