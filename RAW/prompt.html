Variables & Workflow Overview

Before the prompt string is built, the Flask server extracts the original test layout from the targeted past-paper year inside the /api/generate-rag-exam endpoint. Below are the key variables involved in the batch processing and prompt setup:

Core Prompt Variables

Variable Name Data Source Description & Purpose
subject HTTP POST JSON Payload The target test subject (e.g., "Biology", "Chemistry", or "Physics"). Used to filter vector lookups and label questions.
batch_offset ThreadPool Loop The 0-based global index tracking the starting position of the current batch (e.g., 0, 10, 20).
batch_qs Sequence Template slice A list containing up to 10 template dictionaries corresponding to the active batch chunk.
batch_count len(batch_qs) The total number of questions to build in the current batch (typically 10).
chapter_contexts ChromaDB query results A dictionary mapping chapter titles to FSc textbook syllabus notes. Populated during step 4 using embeddings.

Understanding the Concurrency Loop

To prevent timeouts, the engine divides the required question count into batches of 10 and processes them in parallel using a thread pool. Inside each thread, the process_single_batch(batch_offset, batch_qs) worker function is invoked. This function dynamically constructs the prompt, sends it to Groq, and returns the generated structured questions.

# Division into batch workers
with ThreadPoolExecutor(max_workers=5) as executor:
    futures = []
    for offset in range(0, count, batch_size):
        batch_qs = selected_template_qs[offset:offset+batch_size]
        futures.append(executor.submit(process_single_batch, offset, batch_qs))
